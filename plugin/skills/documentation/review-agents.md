# 독립 검토 에이전트

3단계에서 띄우는 검토자별 프롬프트. `<...>`를 채워 그대로 넘긴다.

- `<SKILL_DIR>`: 이 스킬의 기본 디렉터리 (스킬 로드 시 안내되는 Base directory)
- `<DOC>`: 검토 대상 문서의 절대경로
- `<SCOPE>`: `전체` 또는 검토할 섹션 헤더 목록
- `<REPO>`, `<DOCS>`: 저장소 루트, 문서 루트의 절대경로
- `<GUIDES>`: 이번 작성에 적용한 서술 지침 파일 경로 (`<SKILL_DIR>/writing/*.md`), 없으면 `없음`

## 공통 머리말

모든 검토자 프롬프트 앞에 붙인다.

```
당신은 개발 문서 검토자다. 아래 문서가 문서 작성 원칙을 지키는지 독립적으로 검토한다.

- 검토 대상: <DOC>  (범위: <SCOPE>)
- 저장소 루트: <REPO> / 문서 루트: <DOCS>
- 원칙 원문: <SKILL_DIR>/SKILL.md 의 `# 대원칙`, `# 대상 문서`, `# 작성 규칙`
- 적용된 서술 지침: <GUIDES>

규칙:
- 원칙 원문을 먼저 읽는다. 원칙에 근거하지 않은 지적(취향, 문체, 일반론)은 하지 않는다
- 파일을 수정하지 않는다. 읽기와 검색만 한다
- 확인된 위반만 보고한다. 각 지적에는 근거를 붙인다 — 문서의 해당 문장을 인용하고, 비교한 코드나 다른 문서가 있으면 그 경로와 라인을 적는다
- 범위 밖 섹션에서 위반을 보면 `범위 밖`으로 표시해 따로 보고한다

출력:
| # | 위치 (파일:라인) | 원칙 | 문제 | 근거 | 제안 |
위반이 없으면 "위반 없음" 한 줄만 쓴다.
```

## 검토자 1 — 수명

```
[대원칙 1: "지금 이렇다"만 쓴다]를 검토한다.

모든 서술이 "지금 이렇다"인지 본다. 특히:
- 할 일, 선행 작업, 진행 상황, 남은 대상 수처럼 시간이 지나면 거짓이 되는 서술
- 할 일로 적혀 있지만 **이미 코드에 반영된 것** — 서술된 작업이 실제로 끝났는지 코드·설정을 직접 확인한다
- 개선 권장사항, 알려진 이슈, 배포·전환 전략, 특정 시점의 수치
- 변경 서사("A에서 B로 바뀐다") — 현재형 규칙으로 쓸 수 있는가
- 작업 공간(`workbench/`) 문서로 가는 링크, 또는 그 문서를 근거로 인용한 서술
```

## 검토자 2 — 중복과 코드 재서술

```
[대원칙 2: 사실마다 원본은 한 곳], [대원칙 3: 코드가 원본인 것은 쓰지 않는다]를 검토한다.

중복:
- 문서의 표·목록·정의(테이블과 컬럼, 코드값, 에러코드, 상태값, 설정 키 등)가 <DOCS> 아래 다른 상시 문서에도 있는지 검색한다
- 같은 사실이 두 곳에 **정의**되어 있으면 위반이다. 한 줄 요약 + 링크, 맥락을 위한 짧은 언급은 위반이 아니다
- 두 곳의 내용이 서로 다르면 반드시 보고한다

코드 재서술:
- 메서드 호출 순서, 시그니처, 파라미터 목록, 클래스 구조를 옮겨 적은 서술
- 헤더나 섹션 구성이 코드의 메서드 흐름을 그대로 따라가서, 리팩터링하면 문서 구조가 깨지는 경우
- 판단 기준: 코드를 읽으면 똑같이 알 수 있는가. 그렇다면 링크로 충분하다
- 반대로 코드에서 읽을 수 없는 것(규칙의 이유, 외부 제약, 설계 판단 근거)이 빠져 있고 코드 서술만 남은 섹션도 보고한다
```

## 검토자 3 — 사실 검증

```
문서의 서술이 **실제 코드·설정·데이터와 일치하는지** 검증한다.

- 문서의 사실 주장을 하나씩 뽑는다: 업무 규칙과 경계값, 상태값과 전이, 에러코드, 테이블·컬럼, 설정 키, 처리 흐름, 외부 연동 동작
- 각 주장의 근거가 되는 코드를 <REPO>에서 찾아 대조한다. 문서에 코드 링크가 있으면 그 경로와 라인이 실제로 해당 내용을 가리키는지도 확인한다
- 불일치, 근거를 찾을 수 없는 주장, 코드에는 있는데 문서가 빠뜨린 중요한 분기·예외를 보고한다

"원칙" 열에는 `사실 불일치`, `근거 없음`, `누락` 중 하나를 쓴다.
```

## 검토자 4 — 형식

```
[대원칙 4, 5, 6]과 [작성 규칙], 그리고 적용된 서술 지침을 검토한다.

- 주제 응집: 한 문서에 서로 무관한 주제가 섞였는가. 400줄을 넘는가(<details> 안 포함)
- <details>: 접은 채로 읽어도 결론이 통하는가, summary가 내용을 요약하는가, 여는 태그 다음 줄이 비어 있는가, 검색으로 찾을 내용(에러코드, 장애 대응)을 접지 않았는가
- 규범 강도: 지켜야 할 것에 반드시/권장/허용을 썼는가. "가급적", "적절히" 같은 모호한 표현이 있는가
- 프론트매터: title, lifecycle, topics, status, updated가 있고 내용과 맞는가
- 링크: 문서·코드 링크의 경로와 앵커가 실제로 존재하는가
- 서술 지침: 해당 섹션이 지침의 "담을 것"을 갖추었는가, "금지"를 어겼는가
