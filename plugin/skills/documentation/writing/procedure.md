# 절차·장애 대응을 쓸 때

환경 구성, 배포, 정형 운영 작업, 장애·알림 대응처럼 **순서대로 수행하는** 내용에 적용한다.

## 작업 절차

- **목적** 한 문장 — 끝나면 무엇이 되어 있는가
- **전제조건** — 필요한 권한, 설정, 선행 작업
- **단계** — 번호 목록. 각 단계는 실행 가능한 명령·경로·설정값. 치환할 값은 `<>`로 표시하고 바로 아래서 설명
- **확인** — 성공했는지 판정할 관찰 가능한 증거(로그 문구, 응답, 화면)
- **되돌리기** — 운영 환경이나 공유 자원을 건드리면 반드시

## 장애·알림 대응

항목 하나 = 알림 하나 또는 증상 하나. 헤더에 **알림명이나 에러 메시지 원문**을 그대로 쓴다.

1. **영향** — 무엇이 안 되는가, 사용자에게 보이는가
2. **진단** — 실제 명령·쿼리·대시보드 링크. "로그를 확인한다"가 아니라 명령
3. **완화** — 서비스를 먼저 살리는 조치. **원인 설명보다 앞에** 둔다
4. **복구·롤백** — 번호 절차와 되돌리는 방법
5. **에스컬레이션** — 몇 분 내 미해결 시 누구에게

알림을 발송하는 코드가 있으면 발송 조건·채널·메시지 형식을 함께 적어, 받은 사람이 이 항목에 바로 도달하게 한다.

## 금지

- 판단 떠넘기기 — "환경에 맞게 적절히 설정"
- 계정·토큰·접속 정보. 보관 위치만 가리킨다
- 구조적으로 제거된 문제를 계속 남겨두기. 삭제한다
- 위험한 조치(데이터 변경, 강제 재기동)를 경고 없이 쓰기
