# 개발 규범을 쓸 때

코딩 스타일, 검증·예외·로깅 패턴, 테스트 작성 규칙, 브랜치·커밋·리뷰 절차처럼 **개발자가 지켜야 할 규범**에 적용한다. 비즈니스 규칙은 [rules.md](rules.md)로.

## 담을 것

- **조항 + 강도 + 이유 한 줄.** 이유 없는 규범은 지켜지지 않는다
- **자동 강제 여부.** linter·포매터·CI 체크가 잡는지, 리뷰로만 잡는지. 도구로 강제할 수 있는 조항은 문서보다 도구에 넣는다
- **적용 범위.** 대상 모듈과 기존 코드 소급 여부
- **올바른 예 / 잘못된 예** — 오해가 잦은 조항에 한해 최소 코드로 짝지어
- 예외가 허용되는 조건과 코드에서의 표기 방법

## 금지

- **도입 과정 서술** — 도입 배경, 선행 작업, 마이그레이션 절차, 남은 대상 수. 전부 시점 내용이다. 도입이 끝나면 현재 규범만 남긴다
- 테스트 개수, 커버리지 같은 현재 수치
- 상위 저장소나 팀 공통 문서에 있는 규범 복제. 링크하고 **이 저장소에서 다른 점**만 쓴다
- 라이브러리 공식 문서 재서술
